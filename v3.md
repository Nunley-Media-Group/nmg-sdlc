## Product

nmg-sdlc is an Oh My Pi extension and a Herdr workflow, not a Codex plugin wearing a compatibility layer. Users invoke `/plan /skill:…` and `/skill:execute` the same way they invoke any other OMP skill or Herdr agent.

Humans stay at the keyboard for judgment: grooming issues and approving specs inside native OMP `/plan`. Delivery after an approved spec is unattended Herdr `omp` workers unless a step fails.

Spec-driven delivery stays: Given/When/Then acceptance criteria, `requirements.md` / `design.md` / `tasks.md` / `feature.gherkin`, steering docs, evidence-backed verify, and exact-head merge.

Breaking 3.0 drops Codex packaging and vocabulary (the `$` skill alias surface, `<proposed_plan>`, `.codex-plugin`), drops epics, drops cumulative multi-issue specs, and drops interactive gates on automated stages.

The toolkit remains stack-agnostic. Project `steering/` owns language, test, and version details.

Reuse before invent. Use native OMP `/plan`, `ask`, `local://`, `xd://propose`, skills, agents, and `package.json` `omp.extensions`. Use Herdr `pane` / `agent` / `notification` / `integration`. Do not wrap those primitives in nmg-pi shims. Do not reimplement them.

### Principles

- Interactive surface is native `/plan` + `ask` + `xd://propose` for `draft-issue`, `write-spec`, `onboard-project`, and `upgrade-project`.
- Coordination is not a type: there is no epic. Sequencing is `Depends on:` between ordinary issues.
- Automation is Herdr-native: sibling `omp` panes in the user's live session, not a plugin daemon and not in-process `task` workers for pipeline steps.

Implementation of this file rewrites `steering/product.md` to these principles.

## Runtime contract

### Environment

Automated delivery requires `HERDR_ENV=1`, `HERDR_SOCKET_PATH`, and `HERDR_PANE_ID` (Herdr 0.8.0 OMP hook contract). If any is unset, `/skill:execute` prints that it is not inside Herdr and stops without mutation.

`/plan /skill:draft-issue` and `/plan /skill:write-spec` run in any interactive OMP session. Herdr is optional for those skills.

Worker kind is Herdr `--kind omp` only. Installed kinds also include `pi`; do not use `pi`.

Reuse the official integration already installed at `~/.omp/agent/extensions/herdr-omp-agent-state.ts` (`herdr integration install omp`). Do not ship a second pane.report-agent hook from nmg-sdlc. Query `herdr integration status` at execute preflight; if `omp` is missing, print `Run: herdr integration install omp` and stop.

nmg-sdlc is self-contained on OMP + Herdr. It does not require nmg-pi. Do not call the nmg-pi input or plan-mode tools. If nmg-pi is installed and shadows `/plan`, skills still follow the native contract: read-only tree, `ask`, `local://`, `xd://propose`.

GitHub remains the only tracker (`gh` CLI + GraphQL where already used).

OS-agnostic Node 20+ ESM scripts stay for deterministic classification. Herdr CLI is the process supervisor.

Stay in the caller's Herdr session and workspace. Do not create `herdr --session …` or a new workspace, tab, or worktree unless the user already started execute there.

### Pane and agent rules

- Orchestrator stays in the calling pane. Workers are siblings. Splits use `--no-focus`.
- Wide pane → split `right`. Tall or narrow pane → split `down`.
- `herdr agent start` never creates layout. Split first. The target pane must be an idle shell.
- Agent names match `^[a-z][a-z0-9_-]{0,31}$` and are unique among live agents: `s<issue>-<step>`, for example `s42-implement`. Herdr max is 32 characters. Do not use the `sdlc-` prefix.
- `herdr agent start` timeout default is 30000 ms, max 300000 ms. Keep the default.
- Orchestrator never closes a pane it did not create.
- Never run `herdr server stop`.
- Worker prompts must forbid `ask` and any nmg-pi input tool. Herdr 0.8.0 OMP hook reports those UIs as `blocked`, which is a keep-open stop.

## Issue and spec model

### Issues

Types: `feature` (`enhancement`), `bug`, `spike`. No `epic` type, label, or template.

The `draft-issue` classification gate has three options only: Bug / Enhancement / Spike. Delete the Epic option and all `epicRecommended` logic.

Multi-ask prompts still split into multiple ordinary issues. Wire only `Depends on:` / `Blocks:` body lines. No native parent/sub-issue epic graph, no `epic-child-of-N` labels, no Child Issues checklist as coordination identity.

`Depends on:` remains the execution DAG. An issue is blocked while any listed parent is not `CLOSED`.

Spikes still produce an ADR under `docs/decisions/` via `write-spec` Phase 0. Then `execute` skips implement/verify and runs deliver only.

### Specs

One issue owns exactly one spec directory. No cumulative plural Issues frontmatter. No per-issue ownership manifest file.

Directory name: `specs/{N}-{slug}/` where `N` is the issue number and `slug` is the existing kebab derivation from `references/feature-naming.md` (lowercase, non `[a-z0-9-]` → `-`, collapse/strip hyphens). Example: issue 71 titled "Add dark mode toggle" → `specs/71-add-dark-mode-toggle/`.

Classifier prefixes `feature-` and `bug-` are not used for new directories. Variant is the issue label plus heading (`# Requirements:` vs `# Defect Report:`).

Required artifacts for feature/bug: `requirements.md`, `design.md`, `tasks.md`, `feature.gherkin`. Spike: ADR only, no Gherkin.

Frontmatter on every feature/bug spec file (exact field names):

```markdown
**Issue**: #N
**Date**: YYYY-MM-DD
**Status**: Draft | Approved
**Author**: Full Name
**Related Spec**: specs/{M}-{slug}/
```

`**Related Spec**` is required on defects (existing rule) and optional on features when the new issue continues a prior shipped spec. It is a pointer, not ownership sharing.

`## Change History` has exactly one row for that issue (`Initial feature spec` / `Initial defect report` / `Spec revised before delivery`). Revising a spec before first merge updates Date/Status and appends a revision row for the same issue. After merge, a new issue creates a new directory.

Issues drive spec create/update: `/plan /skill:write-spec #N` creates `specs/{N}-{slug}/` or rewrites that same directory while the issue is still open and undelivered. It never writes into another issue's directory.

Specs drive delivery: `execute`, implement, verify, and deliver refuse to run if the matching spec directory is missing or `**Status**` is not `Approved`.

Every spec file's `**Issue**` must equal the directory's leading number. Skills fail closed on mismatch.

### Backlog (first item)

Deterministic order used by `execute` with no args:

1. List open issues in the current repo (`gh issue list --state open --limit 100 --json number,title,labels,body`).
2. Drop issues whose body `Depends on:` parents are not all `CLOSED` (hydrate those parents). GraphQL failure → stop, do not guess ready.
3. Drop issues whose every readable GitHub Project status is `Done` (case-insensitive). Unreadable or absent Project is not Done.
4. Sort remaining by issue number ascending.
5. The first row is the default target.

If that issue has no approved spec, stop and print `Run /plan /skill:write-spec #N`. Do not draft or spec automatically.

No-epic upgrade semantics live in [Upgrade path](#upgrade-path).

#### `draft-issue`

Remove epic classification, epic template, child fan-out, and `coordinationParentNumber`. Keep feature/bug/spike templates as the **execution payload** inside the plan. Multi-issue split: one `ask` confirms the split; one plan lists every issue in topo order with `Depends on:`.

- Slug `draft-<kebab>`. File `local://draft-<slug>-plan.md`.
- Plan contains exact classification (`feature` | `bug` | `spike`), title, milestone or `null`, labels, full issue body, and `gh issue create` argv. Approved execution runs only those commands — no second interview.

#### `write-spec`

Remove the Epic Role gate, umbrella publication, aggregate/link/ownership-manifest files, and the three sequential review gates. One `/plan` cycle authors the whole package.

- Discovery: `specs/{N}-{slug}/` exists → update; else create.
- Slug `spec-<N>`. File `local://spec-<N>-plan.md`.
- Plan Approach includes the full text of `requirements.md`, `design.md`, `tasks.md`, and `feature.gherkin` (spike: ADR path + body under `docs/decisions/`). Approval writes those files exactly and sets `**Status**: Approved`.

#### `onboard-project` / `upgrade-project`

Same `/plan` + `ask` + `xd://propose` contract. Mutation happens only after OMP plan approval. Generated CONTRIBUTING/AGENTS text uses the invocation list above.

### Automated skill edits

Remove every nmg-pi input-tool, `ask`, and plan-approval gate from `start-issue`, `write-code`, `simplify`, `verify-code`, `open-pr`, and `address-pr-comments`. Calling `ask` in a worker is a contract violation (Herdr `blocked`).

On a missing precondition (dirty tree, no spec, blocked dependency, verify Fail, merge not CLEAN), write the handoff with `status: "failed"` and `intervention: true`, then stop. Do not ask.

- `start-issue #N`: no picker, no milestone gate, no "ready to start?" gate. Re-prove `Depends on:` readiness; create/checkout `gh issue develop N --checkout --name N-slug`; set Project to In Progress best-effort. Explicit epic guard is deleted; an `epic` label is treated as an ordinary issue and `upgrade-project` is what removes the label later.
- `write-code`: no plan-mode user approval. Load `specs/{N}-{slug}/` only. Execute `tasks.md` in order. Bundle `simplify` in-process at the end. Skill-bundled files route through `/skill:skill-creator` when that skill is loaded; if it is missing, fail the handoff (`reasonCode: skill_creator_missing`). Do not hand-edit skill bundles.
- `verify-code`: the Herdr worker **is** agent `architecture-reviewer`. Write `specs/{N}-{slug}/verification-report.md`. Comment on the issue. `status: "passed"` only for Pass. `PR Evidence Pending` is `status: "passed"` with `next: "deliver"`. Fail / Partial / Incomplete → `failed`.
- `open-pr`: apply version bump from `steering/tech.md` label matrix automatically. Never infer major; if the issue body/title contains `BREAKING` and the spec has no approved major note, fail closed (`reasonCode: major_bump_required`). Terminal exact-head merge + issue close stay mandatory. Bot review threads (`bots: true` plus `coderabbitai`) are fixed in the same deliverer session via `address-pr-comments`. Human-reviewer threads → `failed` + `intervention: true`, pane stays open.
- `status`: recommend `/skill:execute` or `/plan /skill:write-spec #N`. Drop `epicAuthority`. Keep dependency blocked/ready. User-facing text never uses Codex `$` skill aliases.

### New skill `skills/execute/SKILL.md`

Frontmatter:

```yaml
---
name: execute
description: "Orchestrate automated delivery for approved specs through Herdr OMP worker sessions. Use when the user says execute, run the backlog, ship the next issue, /skill:execute, or passes issue numbers to deliver. Defaults to the first ready backlog issue. Accepts a space-separated list of issue numbers. Do NOT use to draft issues or write specs."
---
```

Argument grammar (exact):

- Trim `$ARGUMENTS`.
- Empty → resolve default backlog issue ([Issue and spec model](#backlog-first-item)).
- Otherwise split on whitespace. Each token must match `^#?\d+$`. Collect unique numbers in the given order (first occurrence wins). Any other token → print `Usage: /skill:execute [#N ...]` and stop non-zero.
- Cap the list at 20 issues. Longer → stop.

Per-issue pipeline (one issue to merge before the next begins):

1. `preflight` (orchestrator, no worker): `HERDR_ENV` / `HERDR_SOCKET_PATH` / `HERDR_PANE_ID`, `herdr integration status` shows `omp`, `gh auth status`, clean worktree OR current branch already equals `{N}-{slug}` from a prior failed run.
2. If no approved spec → stop the queue; do not start later issues.
3. If no linked branch / not on `{N}-{slug}` → worker step `start`.
4. If spike label → skip implement/verify; go to `deliver`.
5. Worker step `implement` (`/skill:write-code #N` then bundled simplify).
6. Worker step `verify` (`/skill:verify-code #N`).
7. Worker step `deliver` (`/skill:open-pr #N`).
8. On deliver success, delete local branch only after `MERGED` + issue `CLOSED` (existing open-pr proof). Then proceed to the next issue in the list.

Dirty tree on execute: fail closed unless the current branch is already `{N}-{slug}` (resume). Do not stash or discard user work.

## Orchestration

This is the load-bearing runtime. An implementer must not invent another topology.

### Orchestrator duties (main OMP session only)

- Read this skill and the Herdr skill (`herdr --skill` / `skill://herdr`).
- Never edit product code, never implement tasks, never open PRs itself.
- Persist run state after every transition to `.omp/sdlc/run.json`:

```json
{
  "schemaVersion": 1,
  "issues": [42, 57],
  "currentIssue": 42,
  "currentStep": "verify",
  "completed": { "42": ["start", "implement"] },
  "failed": null,
  "startedAt": "ISO-8601"
}
```

Also append `pi.appendEntry("com.nmg-sdlc.run", <same object>)` when `ExtensionAPI` is available so a compacted main session can rebuild. File on disk is authoritative if they disagree.

### Worker launch sequence (exact)

1. `herdr pane layout --pane "$HERDR_PANE_ID"` → if width ≥ height, `right`, else `down`.
2. `herdr pane split --current --direction <dir> --cwd "$PWD" --no-focus`
3. Read `.result.pane.pane_id`.
4. `herdr agent start s<N>-<step> --kind omp --pane <pane_id>`
5. `herdr agent prompt s<N>-<step> "<prompt>" --wait`
6. Interpret settled state from the prompt result / `herdr agent get`.

Worker prompt (exact shape; fill tokens):

```text
You are the nmg-sdlc <step> worker for issue #<N>.
Read skill://<skill> and execute it for #<N> with no user questions.
Write the handoff file then stop.

Handoff path: .omp/sdlc/handoffs/<N>-<step>.json
On success print exactly: NMG_SDLC_HANDOFF: .omp/sdlc/handoffs/<N>-<step>.json
```

After `herdr agent start`, the prompt must include `/skill:<skill> #N` so the worker loads only that skill.

`<step>` → skill map: `start` / `start-issue`, `implement` / `write-code`, `verify` / `verify-code`, `deliver` / `open-pr`.

### Handoff file schema

The worker writes the file. The orchestrator reads the file, not the TTY, as source of truth — Herdr documents alternate-screen loss.

```json
{
  "schemaVersion": 1,
  "issue": 42,
  "step": "verify",
  "status": "passed",
  "intervention": false,
  "summary": "one paragraph",
  "artifacts": ["specs/42-slug/verification-report.md"],
  "next": "deliver",
  "reasonCode": null
}
```

`status` enum: `passed` | `failed` | `blocked`. `intervention` is `true` whenever the pane must stay open.

### Close vs keep

| Settled condition | Action |
|---|---|
| Agent `idle` or `done` AND handoff `status=passed` AND `intervention=false` | Read summary into orchestrator context; `herdr pane close <pane_id>`; advance step |
| Agent `blocked` | Keep pane; notify; set run `failed`; stop queue |
| Agent `unknown` or prompt stall `agent_prompt_stalled` | Keep pane; same as failed |
| Handoff missing after idle/done | Keep pane; `reasonCode: missing_handoff` |
| Handoff `failed`/`blocked` or `intervention=true` | Keep pane; stop queue |
| `start`/`implement`/`verify`/`deliver` process error (gh, git, tests) | Worker writes failed handoff; keep pane |

Notification on keep-open — exact command (Herdr 0.8.0):

```bash
herdr notification show "nmg-sdlc stopped" --body "Stopped on #<N> <step>. Worker pane <pane_id> agent s<N>-<step> left open." --sound request
```

If the result reason is not `shown` (`disabled` | `rate_limited` | `no_foreground_client` | `busy`), still print the same sentence in the orchestrator pane. That print is required either way.

### Resume

- Re-invoking `/skill:execute` with no args or the same issue: if `.omp/sdlc/run.json` names that issue and a live agent `s<N>-*` exists, do not split a second worker; print the existing pane/agent ids and stop.
- If no live agent and `completed` lists prefix steps, skip those steps.
- If last handoff is `failed` and the user re-runs after fixing in the kept pane, require a new worker only when the old agent is gone. If the old agent is still live and now `idle`, re-read the handoff file; if it is now `passed`, close and continue.

## Upgrade path

`upgrade-project` stays interactive and is the only mutator for existing projects.

Detect and propose, never silent:

1. **Packaging**: if the project consumes nmg-sdlc as a Codex plugin only, report that v3 installs as an OMP plugin (`omp plugin install` / marketplace / `omp plugin link`) and requires Herdr. nmg-pi is optional host chrome, not a v3 dependency. Do not write `~/.codex/config.toml`.
2. **Legacy layout**: keep existing `.codex/{steering,specs}` relocation.
3. **Directory rename**: `specs/feature-{slug}/` or `specs/bug-{slug}/` or legacy `{N}-{slug}/` already matching → rename to `specs/{primaryN}-{slug}/` where `primaryN` is the first issue in plural Issues frontmatter or the singular `**Issue**`. If the target exists, stop that item as collision and ask.
4. **Cumulative split**: if plural Issues frontmatter lists multiple numbers or a leftover ownership-manifest file (`issue-scope.json`) has multiple keys, create one `specs/{N}-{slug}/` per issue. Copy only that issue's `owned` ACs/FRs/tasks/scenarios into the new files (use the leftover ownership-manifest file when valid). Put `adopted` identifiers into the owner issue's spec, not the adopter. Add `**Related Spec**` pointers between the split family. Delete the leftover ownership-manifest file after a successful split. If ownership is `unverifiable`, do not split; report and require a manual choice.
5. **Epic flatten**: for each `specs/epic-*/` and each leftover `epic-link.json`:
   - Each executable child package becomes an ordinary `specs/{childN}-{slug}/` with `**Issue**: #childN`.
   - Append a short `## Historical coordination` note quoting the aggregate goal; do not keep executable tasks on the aggregate.
   - Delete leftover `epic-scope.json`, leftover `epic-link.json`, and the `specs/epic-*` directory after children exist.
   - Propose removing GitHub `epic` / `epic-child-of-N` labels and native sub-issue parent links. Apply only on explicit per-group approval (existing upgrade digest style). Convert any remaining "coordination" edges that are real execution prerequisites into `Depends on:` body lines.
6. **Frontmatter**: plural Issues → singular `**Issue**` with the directory's N. Status `Amended` → `Approved` if the issue is closed, else `Draft` if still open without verification-report.
7. **This repository's archive**: same rules apply to `specs/` in nmg-sdlc itself, including `feature-add-first-class-epic-support-and-multi-pr-delivery-flow-to-nmg-sdlc` and every `bug-*` / `feature-*` directory.
8. Repeat-run: already-linear `specs/{N}-{slug}/` with singular `**Issue**` and no leftover epic artifacts reports `already current`.

Keep ownership-aware cleanup of leftover v2 runner files (`sdlc-config.json`, `.codex/unattended-mode`, `.codex/sdlc-state.json`) as today.
