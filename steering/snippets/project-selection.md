# nmg-sdlc Test Selection Conventions

These conventions apply to this repository's `gate:selection` answer.

- Each test id is the repository-relative path of an existing Jest test file, `scripts/__tests__/<name>.test.mjs`. A name that is no file in the repository makes the gate run the whole suite, so name only test files that appear in the changed paths or the diff, or that you know exist; never derive one from a module name. Never give a runner-relative id such as `__tests__/<name>.test.mjs`, a test name, a pattern, a directory, an absolute path or anything beginning with `-`: the gate refuses them and runs the whole suite.
- Many modules have no test file of their own name: `src/sdlc-<name>.mjs` and `scripts/<name>.mjs` are exercised by the test files whose subject covers them. When you cannot name an existing test file that exercises a changed module, answer `all`. Select every test file whose subject the change can affect, including tests of modules that import a changed module.
- A changed test file must itself be selected.
- Surfaces follow the plugin's shape: one surface per interactive command workflow (`draft-issue`, `write-spec`, `onboard-project`, `upgrade-project`, `steering`, `run-retro`), `execute` for the delivery stages, their agents and controller scripts, `status` and `verify-full` for those commands, `plugin-host` for `hooks/` and `.claude-plugin/`, `shared-references` for root `references/`, `project-steering` for `steering/`, `script-assets` for script fixtures and data files, and `ci` for `.github/`. Select a surface whenever the change touches its sources or a shared file it consumes.
