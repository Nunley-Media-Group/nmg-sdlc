# Interview

Apply the rendered `/sdlc-execute` eligibility algorithm before Interview. Extract only functional software behavior and implementation-relevant technical detail that execute can realize through permitted repository changes and prove through accepted evidence. Omit external obligations instead of moving them into context or boundary sections.

Use `ask` within the total three-question budget only to resolve material product behavior, observable acceptance oracles, and required preferences. Every question includes a short paragraph stating the situation and facts needed to choose among the options. Ask only about executable software behavior; never ask for legal interpretation, policy judgment, ownership or authority proof, external sign-off or attestation, credentials, live operations, or repository facts available through tools.

If filtering leaves no eligible behavior, print exactly `Issue #N has no software requirements executable by /sdlc-execute after excluding non-software obligations.` and stop before plan creation, proposal, branch preparation, file writes, commits, publication, labels, or merge.

If a material choice remains after three asks, print exactly `Issue #N has unresolved decisions required for /sdlc-execute: <comma-separated decisions>.` and stop before plan creation, proposal, or mutation. Never emit Open Questions into the plan's four generated files.

A leftover `spike` label is not an ADR bypass. Always author the ordinary four-file package when an eligible slice remains.
